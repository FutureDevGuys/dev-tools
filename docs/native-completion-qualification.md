# Native completion qualification

The explicit Linux conformance lane sources unchanged generated completion scripts in real Bash, Zsh, Fish, PowerShell and Elvish runtimes. For every public product it checks a root command candidate, the nested `build-info --j` → `--json` candidate and a product-owned deeper option, then removes registration and requires each candidate to disappear in a fresh process. This is bounded native shell evidence, not complete command-tree coverage or native Windows/macOS acceptance.

Build the public binaries from the source under test first. Set `DEV_TOOLS_NATIVE_BIN_DIR` to the absolute directory containing those binaries. Set `DEV_TOOLS_TEST_BASH`, `DEV_TOOLS_TEST_ZSH`, `DEV_TOOLS_TEST_FISH`, `DEV_TOOLS_TEST_POWERSHELL` and `DEV_TOOLS_TEST_ELVISH` to explicitly selected absolute runtime executables, and `DEV_TOOLS_TEST_SCRIPT` to the absolute util-linux `script` executable supporting direct argv after `--`. Zsh requires its `zsh/zpty` module. The tests do not download or discover runtimes, install completions, or modify user startup files. Missing explicit inputs fail the requested lane rather than silently skipping it.

```sh
cargo test --locked -p dev-tools-conformance --test native_completions -- --ignored
```

Each test can also be selected individually by its `native_bash`, `native_zsh`, `native_fish`, `native_powershell` or `native_elvish` name. Test subprocesses use private temporary home/XDG directories, a controlled environment, bounded output and a twenty-second deadline. PowerShell runs without profiles or telemetry. Elvish needs its native editor namespace, so its probe runs in a private PTY with input echo disabled; it inspects the registered argument completer before the editor's final prefix filtering. No replacement editor namespace is injected.

Zsh uses a private [zpty](https://zsh.sourceforge.io/Doc/Release/Zsh-Modules.html#The-zsh_002fzpty-Module) session to drive actual tab expansion without executing the completed product command. A test-only `compadd` wrapper captures native matching candidates using the builtin's documented [`-O` array output](https://zsh.sourceforge.io/Doc/Release/Completion-Widgets.html), then delegates the original call unchanged. The assertion checks candidates rather than assuming one Tab inserts a complete option. The fixture deletes only its own named PTY on exit. Bash invokes its generated registered completion function with native completion variables; Fish uses `complete -C`; PowerShell uses `CommandCompletion.CompleteInput`.

The shared renderer's deep Fish regression is separately runnable with `cargo test --locked -p dev-tools-completion --test render native_fish -- --ignored` using the same explicit Fish path. It checks third/fourth-level options, aliases, values, child suggestions and unrelated-branch rejection. Fish retains upstream token-presence matching limitations; these probes do not prove arbitrary positional grammar or distinguish every subcommand-shaped option value.

Ordinary product suites retain their independent generation and native Bash regression tests. This central opt-in lane adds no sibling-product runtime dependency or requirement to build all products when testing one product. Record source identity and native runtime versions with release qualification evidence; a successful debug-source run does not qualify a different signed release artifact.

Run the shared Elvish option-value regression with `cargo test --locked -p dev-tools-completion --test render native_elvish -- --ignored`, using the explicit Elvish and PTY paths above. It exercises the real [argument-completer interface](https://elv.sh/ref/edit.html#argument-completer) for long/short options, visible aliases, repeated options, sibling isolation and `--` suppression. The renderer retains upstream leading-subcommand path recognition; attached values, positional values, variable arity and options before subcommands are not qualified by this lane.
