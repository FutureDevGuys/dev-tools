# dev-auth

`dev-auth` is a generic post-login credential adapter for one bounded automation principal shared by processes running as the same workstation user. It has no daemon, listener, provider-state model, deployment behavior, arbitrary vault browser, human-credential fallback, or device-specific policy.

The workstation authority writes an owner-only `~/.config/dev-auth/config.toml`, enrolls one 1Password Service Account token into the logged-in user's OS credential store, and starts one dedicated standard OpenSSH agent at `${XDG_RUNTIME_DIR}/dev-auth/ssh-agent.sock`. Logout or reboot removes the runtime token cache and agent keys; each device requires one intentional enrollment because a credential cannot securely retrieve itself.

The configuration admits only explicit numeric GitHub repository IDs under unique owner-bound GitHub App installations, the exact Actions-read, Checks-read, Contents-write, Metadata-read, Pull-requests-write, and Statuses-read permission map, declared `op://Automation/...` fields, absolute child executables, and one authentication plus one signing SSH key fingerprint. Owner and repository text is matched case-insensitively while the numeric repository ID remains the authorization anchor. Configuration and runtime paths reject symlinks, additional hard links, foreign ownership, and group or other access.

Git config uses `credential.useHttpPath=true` and the standard `git-credential-dev-auth` helper only inside an automation-workspace `includeIf` scope. A successful `get` returns a short-lived installation token and its expiry through the Git credential protocol. A failure returns `quit=true`, so Git cannot continue to a human credential helper or prompt. `store` discards input, and `erase` removes only the exact scoped cache entry. See [Git credentials](https://git-scm.com/docs/gitcredentials), [Git credential protocol](https://git-scm.com/docs/git-credential), and [GitHub App installation authentication](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-as-a-github-app-installation).

`gh-dev-auth` resolves one repository from `-R`/`--repo`, `GH_REPO`, or the current Git origin, obtains the same narrowed installation token, and invokes the pinned upstream `/usr/bin/gh` with a child-only `GH_TOKEN`. Its admitted surface covers repository pull requests, Actions run observation, read-only workflow inspection, release downloads, and repository view/clone. Authentication changes, user-level API calls, repository administration, issues, secrets, variables, workflow dispatch, and release publication fail before credential retrieval.

`dev-auth exec --profile NAME -- /absolute/command ...` runs only an executable declared by that profile and supplies only its declared Automation-vault fields. It clears the ambient environment, restores a small runtime allowlist, and never passes the Service Account token to the child. `dev-auth ssh-load --profile NAME` clears and repopulates only the dedicated OpenSSH agent, then requires the loaded SHA-256 fingerprints to exactly equal the profile. The private keys travel to `ssh-add` through standard input and are never written to a persistent file. The same released binary may be linked as `ssh-keygen-dev-auth`; that frontend runs upstream OpenSSH `ssh-keygen` with only the dedicated agent socket and is the scoped Git `gpg.ssh.program`, so ordinary human shells may keep the desktop 1Password agent. `dev-auth purge` removes derived installation-token cache files and clears the dedicated agent.

The 1Password Service Account must have immutable `read_items` access only to the custom `Automation` vault. Its token is an enrollment credential, not an interactive desktop session or a replacement for human 1Password access. See [1Password Service Accounts](https://developer.1password.com/docs/service-accounts/get-started/) and [1Password SSH-agent security](https://developer.1password.com/docs/ssh/agent/security/).

GitHub transport/API identity and commit authorship are intentionally separate. HTTPS Git and the bounded GitHub CLI wrapper authenticate as the GitHub App. Commits and tags use the dedicated automation signing key in the OpenSSH agent. Host authentication uses the other declared key. Higher-risk GitHub administration, workflow modification, public publishing, infrastructure apply, identity administration, and human-vault access remain interactive/elevated operations outside this product.
