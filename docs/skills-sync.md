# skills-sync

`sync` updates explicitly tracked canonical installations through the upstream CLI, then refreshes the lock/inventory, restores missing payloads and reconciles links. It does not request all-source expansion or update untracked/app-owned payloads. Updates require a stable `skills` 1.x version starting at 1.5.25 and a selected lock that resolves to the upstream runtime lock: `~/.agents/.skill-lock.json` globally or `./skills-lock.json` in the project. Historical default lock discovery is unchanged; use `--global-lock-file ~/.agents/.skill-lock.json` when selecting that native global lock. `repair` is the update-free setup route; recognized explicit global agent links are repaired locally without reinstalling an existing canonical payload. Missing payloads and legacy project/unsupported-agent registration can still invoke upstream `add`.

Each provider call has a 300-second timeout, adjustable with `--command-timeout SECONDS` from 1 through 86400, and a 16 MiB per-stream bound. Ctrl-C stops owned provider execution, prevents later planned mutations and exits 130; already-entered upstream changes are not rolled back. Linux inventory listing uses bounded anonymous regular-file stdout to preserve complete Node output; that mode also bounds incidental provider file writes, so use an already-installed provider. A successful update record reports command completion, not proof that upstream could check every source. [The product ADR](../crates/skills-sync/docs/adr/0001-tracked-updates-and-local-link-repair.md) records the compatibility and release boundaries.

The opt-in real-provider acceptance test runs with `SKILLS_SYNC_ACCEPTANCE_NODE=/absolute/node SKILLS_SYNC_ACCEPTANCE_CLI=/absolute/skills/bin/cli.mjs cargo test -p skills-sync --test upstream_acceptance -- --ignored`. It requires the pinned released upstream 1.5.25 and uses an isolated home/project plus a loopback synthetic source; it never changes normal installed skills.

Set `SKILLS_SYNC_ACCEPTANCE_BINARY=/absolute/skills-sync` as well to exercise an explicitly selected installed release instead of Cargo's build. [Linux release acceptance](skills-sync-sync-configs-acceptance.md) records the source-bound Skills Sync 0.2.0 and SyncConfigs 0.2.1 artifacts and rollback evidence.

`skills-sync` reconciles agent skill discovery, locking, linking, adoption, dry-run, and JSON output from explicit public provider definitions. Personal source manifests, agent selection, and managed-lock policy belong to the caller.

Use `skills-sync repair` for the broad repair workflow; preview with `skills-sync repair --dry-run` and retain your existing scope and provider arguments. `doctor` currently remains an equivalent mutating compatibility spelling, and both emit the legacy JSON `command: "doctor"` value. This expansion does not change existing workflows or implement the common read-only doctor. [ADR 0014](adr/0014-skills-sync-explicit-repair-transition.md) defines the release and consumer-migration gates before that later change. Repair can run the selected upstream provider; it is not a network-free diagnostic command.

`skills-sync completion bash|zsh|fish|elvish|powershell` prints static shell code from product-owned command metadata without reading operational environment settings, inspecting skills or locks, invoking an upstream command, or editing startup files. It preserves the existing operational parser and describes implemented commands, including the currently mutating `doctor` workflow; it does not imply completion of the common read-only doctor/update migration.

`skills-sync build-info --json` emits the common checkout-independent `dev-tools-build-info-v1` document without reading lock files or invoking the upstream skills command. The hidden `--build-info` form remains for rollback to the pre-standard 0.1 line and is removed in the next minor release after one accepted release has shipped the standard subcommand.
