# Dev Auth executable acceptance

The general-purpose delivery is governed by the [accepted implementation plan](../context/docs/dev-auth-delivery-plan.md). This inventory distinguishes implementation evidence from installed release and provider evidence; it is not a platform-support claim.

The signed Linux gates are `setup_v3::recovery_native::signed::native_disposable_signed_fresh_install_workload_and_restore` and `setup_v3::recovery_native::signed::native_disposable_signed_legacy_upgrade_and_restore`. Run each only in a separate explicitly owned, rootful, network-free, host-mount-free disposable systemd container with private PID/cgroup/IPC/UTS namespaces and `DEV_AUTH_NATIVE_SYSTEMD_FIXTURE=disposable`. Supply the exact clean signed product release directory at `/signed/candidate` and the authenticated 0.3.11 release directory at `/signed/prior`; do not strip or otherwise modify signed artifact bytes. Both gates use public release verification, plan/apply/verify, a second plan/apply no-op and inactive restoration. Provider material is synthetic. These gates are not satisfied merely by compiling their ignored tests.

## Local observation

`dev-auth doctor [--json]` is local, read-only and network-free. JSON uses `dev-tools-operation-result-v1` with additive `invoked_version` and optional installed `details`. An executable outside the managed version layout reports `external`; a broken versioned installation reports failure rather than being treated as a clean external installation. Non-Linux doctor currently reports `unsupported`.

Installed details distinguish `credential_observation` values `not_required`, `present`, `missing`, `not_observable` and `unsafe`. Observations cover the configured credential slots instead of assuming a slot named `automation`. Protected metadata that the caller cannot inspect is `not_observable`, not proof of missing enrollment. Native user credential stores are not queried by diagnostics. The retained `credential_ready` boolean is true only for positively observed presence or no required slots; callers needing a reason must use the observation field. Neither presence nor readiness proves successful provider authentication: `provider_use_observation` is explicitly `not_checked`. Doctor leaves both session and broker state `not_probed`; `status --broker` remains the explicit local broker-probe interface and now shares the credential observation semantics.

The installed native gate is `CARGO_PROFILE_TEST_DEBUG=0 CARGO_INCREMENTAL=0 cargo test -p dev-auth --locked -j 2 --test cli standalone_doctor_has_no_network_helpers_or_mutation -- --ignored --exact --test-threads=1`. It requires Linux Bubblewrap, strace and strip. The test uses a disposable account view and supplied product copies, bounds its outer child to 150 seconds and one MiB of output, and traces the installed doctor separately from setup. It rejects network calls, helper processes, write-capable opens, renames/removal, installation locks and storage synchronization. This is source-binary native evidence, not a signed-release or live-provider result.

## Explicit invocation results

`dev-auth workload launch NAME [--non-interactive] [--result-file PATH] -- [ARGUMENTS...]` preserves native argument values after `--`. The result destination must be a new absolute file in an existing caller-owned mode-0700 directory; the file is created mode 0600 without following its final symlink or replacing an existing entry. It contains one value-free `dev-auth-execution-result-v1` document, never child output, secret values or caller arguments. No destination is created for a syntactically invalid invocation. An interrupted or failed result write may leave an incomplete document; such a document is not success evidence and is not an authorization receipt.

Uninstalled copies return `requires_setup` with exit 3 and `started=false`. Noninteractive launch cannot enter pkexec or a potentially interactive native credential-store read. The 0.4 Linux source selects the narrow native enrolled dispatcher for explicit strong-mode `enrolled_noninteractive` workload authority; explicit user-only enrolled authority selects the bounded, no-unlock Secret Service reader in [ADR 0065](adr/0065-prompt-free-user-enrollment-read.md). Other noninteractive outer launches return `approval_required`. Unavailable prompt-free enrollment returns exit 3, `started=false` and the fixed `enrollment_unavailable_without_interaction` error before a broker socket or child starts. An existing verified session can execute its configured downstream target without widening that session. Selecting a nested result file uses the retained native child runner and reports `started=true` after child execution. Other exited backend results retain `started=null` where the existing supervisor return type cannot distinguish dispatcher termination from workload execution; errors after entering that boundary likewise preserve uncertainty. Native set-user-ID, signed setup/migration, vendor-store and live caller qualification remain required; source routing does not establish them.
