# Shared command execution

`dev-tools-command` is the product-neutral authority for ordered executable discovery, native `PATH` composition, and bounded execution of an exact caller-selected program inside Dev Tools. It preserves platform search semantics, requires executable files, compares command locations through canonical parent directories, uses the operating system's path-list encoding rather than constructing path strings manually, and captures explicitly bounded output without pipe backpressure.

The crate does not choose which commands are trusted, install launchers, mutate shell configuration, interpret output, or grant credentials. Products retain those policy decisions and must supply the exact executable, arguments, environment, working directory, timeout, and output limit for bounded execution. Dev Cache uses the shared discovery surface for its owned intercept audit, while dev-auth uses the shared path composer for its session-private workload tool plane.

On Linux, `HeldExecutable::open_read_handle` opens an independent read-only handle to the already-retained executable inode through the held, validated procfs directory and checks its device/inode identity. It does not reopen the original pathname. Each handle starts at offset zero and may outlive the holder; it has close-on-exec enabled and does not expose a write access mode. Products own bounded reads, hashing, change detection and acceptance policy. Holding an inode protects against pathname substitution, not authorized in-place modification of its contents. Other platforms retain the unsupported-backend error. This additive API requires a signed registry generation before external adoption.

Held execution is not universally pathname-transparent. Linux supplies a script's execution pathname to its shebang interpreter rather than preserving the caller's original `argv[0]` as the script name; with this backend that is a `/proc/self/fd/` path. A path-sensitive wrapper can therefore observe a different `$0` and lose relative-resource lookup behavior even when its bytes and caller arguments are preserved. The native characterization test compares direct and held execution of the same synthetic script. Consumers requiring transparent wrappers need a separately qualified path-preserving launch mechanism; setting `arg0` alone is insufficient. See the [Linux interpreter-script contract](https://man7.org/linux/man-pages/man2/execve.2.html).

Standard input is closed by default. `run_bounded_command_with_public_input_and_cancellation` and its prepared-command counterpart accept an explicit byte slice of at most 16 MiB and a caller-owned cancellation flag. The existing non-cancellable public-input functions retain their signatures and delegate to the same implementation. Input is binary-safe and staged in an anonymous temporary file, so a child that does not read cannot block a pipe writer. This is public-data input only: staging may use persistent storage and provides no secure-erasure guarantee. Secret projection needs a separately admitted product-owned mechanism.

Invalid requests, resource limits, and oversized input fail before cancellation is evaluated. Cancellation is checked before staging and again before changing standard I/O or spawning. Staging uses synchronous filesystem operations; the timeout bounds child execution, not temporary-file I/O. After execution, success or failure releases the runner's staged handle from the caller-owned prepared command and leaves stdin closed. Caller-owned executable identity, arguments, environment, working directory, and child setup remain intact.

Once started, input-bearing commands use the same timeout, output bounds, cancellation, retained process-domain cleanup, and typed primary/secondary errors as closed-input commands. On supported Unix targets the runner terminates its owned process group before returning; this does not contain descendants that deliberately escape that group. Other targets retain the documented direct-child-only boundary. These APIs add neither interactive streams nor a new process controller. See [ADR 0010](adr/0010-cancellable-public-command-input.md); source checks alone do not establish native platform acceptance.
