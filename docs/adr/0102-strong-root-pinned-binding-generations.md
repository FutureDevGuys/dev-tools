# ADR 0102: Strong root-owned pinned binding generations

status: proposed
verification: pending

## Decision

A strong Linux binding may select pinned code only when its canonical executable and every path ancestor are root-owned and not group/world writable. User-only pins, user-writable targets, and pathnames that cannot be encoded unambiguously in one native systemd mount property fail before setup mutation; an operator may instead deliberately select mutable trust. Pinned shell definitions remain a separate permission and source-custody contract, not an implicit extension of this path.

Full setup captures the approved target identity, publishes a root-owned copied payload through one nested versioned-installation ledger for that exact account, alias, generation and digest, verifies the artifact before publishing the binding-set receipt, then activates receipt-owned aliases last. Each generation has a distinct immutable ledger and private internal link plane. A successor never swaps or deletes the retained prior generation: the shared versioned rollback operation changes previous-history shape and may remove an older artifact, so it cannot restore the outer setup generation exactly. The binding-set receipt records only active pinned artifact identities; the nested ledger owns bytes and an exact receipt. Pending recovery accepts only the approved target bytes and exact nested candidate transition. Accepted repeat recovery checks the retained copied artifact without reopening a later-edited original target.

At launch the authenticated root dispatcher selects the active root-custodied binding generation for the exact owner, workload and configured launcher, verifies its nested artifact and asks the transient systemd service to bind the copied file read-only at the original root-owned pathname under `PrivateMounts=yes`. The admitted non-root child verifies the projected pathname and copied artifact have the same device/inode and approved digest before execution; nested and sandbox children repeat that check. This preserves shebang pathname and adjacent resource behavior while avoiding the user-writable-parent replacement counterexample. The normal workload identity, supplementary groups, cwd, environment, streams, terminal, signals, broker and cgroup lifecycle remain separately owned by the existing strong boundary. No caller path, alias string alone, environment hint or arbitrary PID selects a payload.

When several aliases select the same pinned workload launcher, they must approve the same byte identity. The dispatcher checks every copied store and projects the first alias in canonical order. The child checks that selected artifact's inode and digest at the launcher; other aliases have distinct copied inodes and are not falsely required to match one mount inode.

The setuid root dispatcher itself is the fixed receipt-owned privileged launcher, not the version-layout executable. Binding selection therefore uses its independently verified launcher installation receipt at that boundary; versioned worker and user processes retain their ordinary running-executable validation. A library test binary outside either installed shape cannot stand in for the dispatcher when probing this authority.

Restoration retires public integrations and restores the prior binding receipt, then removes only an exact candidate nested store; the prior store remains byte-for-byte unchanged. A crash before the nested ledger journal may leave an exact copied payload; restoration recognizes that partial state and removes only its approved bytes and owned empty directories, failing closed on unknown content. Initial absence and repeat restoration are distinct. After full setup acceptance, the native root owner inventories the product's root-owned pinned store account plane under the setup exclusion, including accounts retired before the current generation. It verifies each account parent before opening any retirement marker and preserves every pinned active and previous generation referenced by the accepted and retained-prior binding receipts. Each account's artifact and link trees, completed nested receipts, and exact store entries are checked before a superseded store receives a root-owned retirement marker. Exact, optional links, receipt and payload are then removed through an idempotent owned retirement sequence; the marker is removed last, allowing accepted setup recovery to replay a crash between unlink steps. A new setup plan refuses a pending marker until that accepted recovery completes. Unknown or partial unmarked store content stops collection without treating it as permission to delete. A missing or mismatched retained store is a failed postcondition, not permission to use the original target or downgrade to mutable trust.

An unchanged accepted pin may be carried into a setup-owned version update after its original root-owned script changes. Update preparation authenticates the current binding receipt and nested copied artifact, then rebases the exact retained intent and resolved identity against that receipt without reading the original script. Pending setup rechecks the nested artifact. New pins, changed targets, refreshes and rebinds still require inspection of newly approved source bytes. The ordinary setup path can use this same narrow unchanged-pin rule only when the current receipt and exact copied artifact match; a plan cannot invent a pin from an absent store.

## Verification and remaining gates

Source tests cover root-owned pin planning, per-generation exact payload copies, no-op repeat, wrong-generation collision, original-path property encoding, retained prior preservation, exact pre-journal copied-payload and nested commit-journal recovery, restoration, superseded-store collection, foreign-content refusal, owned candidate removal, and source-free accepted plan structure. Separate source child processes now exit abruptly after marker publication, each link/receipt/artifact/directory removal, and lock removal; every boundary replays to exact owned absence. A disposable rootful systemd fixture passed the pinned alias, read-only systemd projection probe, script-relative resource, nested launch, later edit of the original root-owned script, initial and repeat accepted recovery, inactive owned restoration alongside mutable binding, and native root-owned three-generation store collection that retained active/prior bytes before owned removal. A separate native child exited abruptly after the retirement receipt unlink; the marker-backed retry removed only its exact superseded store and retained active/prior bytes. Another replay prepared the accepted setup-owned update source snapshot after original pin-source drift and confirmed the rebased pin remained unchanged against its active copied artifact. Other native nested publication and retirement interruption points, full UID/GID groups, terminal/signal behavior, sandbox adapter interaction, a signed version-changing update apply, signed distribution and non-Linux backends remain open. This source candidate is not a supported pinned-binding release.
