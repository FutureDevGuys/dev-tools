# ADR 0057: Retained native service shutdown

status: proposed
verification: pending

## Decision

The Linux retained-installation component has fixed operations for observing, disabling and stopping the two Dev Auth broker sockets and broker service, and for reloading restored service definitions. Mutation requires effective root, canonical system installation paths, an admitted inactive retained product receipt, inactive transparent paths and root-owned ordinary unit files whose exact digests belong to the original or candidate receipt. The enclosing full-generation owner retains setup exclusion and durable restoration direction. This component does not expose arbitrary unit names, commands, destinations, credentials or privilege acquisition, and does not enable the still-gated public strong restoration operation.

The native adapter invokes only validated `/usr/bin/systemctl` with direct fixed arguments, a cleared controlled environment, root working directory, closed input, no pager or authentication prompt, bounded captured output and a shared 60-second command budget per component operation. It uses the shared owned-process command runner. A failed or timed-out request never establishes service completion. A stop job already accepted by systemd may continue under the manager after its requesting process ends; retained restoration reports uncertain entered progress and must re-observe before subsequent file mutation.

Machine-readable observations require the exact selected unit ID, loaded state, fixed unit-file path, no unretained drop-ins, supported activation state and an empty or exact product cgroup path. Duplicate, missing or foreign fields fail closed. A stopped unit must have a matching inactive/dead or failed/failed state pair, no main/control PID and no pending job. Enabled persistent and runtime activation links are disabled before a required stop request. Read-only kernel workload absence is required before shutdown; broker and workload domain absence and broker socket absence are required afterward. Restoration does not kill arbitrary processes discovered by name or adopt unrelated unit ownership.

Kernel absence observation retains the canonical root-owned `system.slice` directory and checks the actual cgroup-v2 filesystem identity. Enumeration is bounded, product workload names use the existing native admission grammar, and child/event observations are descriptor-relative and revalidated. Only an explicit, unambiguous `populated 0` permits an extant domain to count as empty. This field includes descendants; a zero main PID or an empty direct-process list is not substituted for it. Ordinary files cannot forge native cgroup evidence. These checks complement the enclosing admission lease and stopped broker; they do not create atomic exclusion against an independent root writer. The kernel contract is documented in the [cgroup-v2 population interface](https://docs.kernel.org/admin-guide/cgroup-v2.html#un-populated-notification).

After document and binary restoration, the component reloads service definitions only when observation requires it, then verifies inactive units, no pending reload, empty execution domains and absent sockets. Terminal verification is read-only. Already-inactive retries do not submit another disable or stop request. The system manager's observation and request semantics follow its [machine-readable show and job interface](https://github.com/systemd/systemd/blob/main/man/systemctl.xml); request completion is kept distinct from the kernel execution-domain postcondition.

## Evidence

The shutdown orchestration test failed at the absent operation before implementation. It checks fixed disable/stop ordering, unchanged read-only retry, rejection before mutation when a workload remains, and failure when domain population remains despite a successful stop request. Parser and argument tests reject unowned unit files, drop-ins, ambiguous properties, unsupported activation states and nonterminal PID/job observations; reload tests preserve the stopped prerequisite and unchanged repeat.

The cgroup parser test likewise failed before implementation. It checks explicit empty/populated states, malformed or duplicate observations and bounded input. A filesystem test requires ordinary fixture files to fail native evidence admission. The ignored `native_system_slice_population_includes_its_running_descendants` and `native_fixed_service_observations_use_bounded_read_only_queries` tests exercise real system-slice descendant population and bounded observations of installed fixed Dev Auth units. Select either test by its full name with `--exact --ignored`; these two tests do not stop, disable, reload or otherwise mutate installed services.

The separately ignored `setup::restoration::service::tests::native_disposable_systemd_shutdown_removes_sockets_and_is_idempotent` test requires root, `DEV_AUTH_NATIVE_SYSTEMD_FIXTURE=disposable`, a container marker, systemd PID 1 and absent fixed product unit files before creating its fixture. Run it only in an owned disposable container with private cgroups, no network and no host mounts; the outer runner owns cleanup even after failure. It creates the compiled product unit files, activates both sockets, then requires native stopped-unit, kernel-domain and socket-absence evidence plus unchanged stop and synchronization retries. It does not launch a broker process or exercise credentials. This native socket shutdown test passes; the combined fixture below covers root-generation composition, while process-death recovery, active-broker termination and signed full-generation acceptance remain required before complete strong restoration is supported.

The disposable Fedora fixture initially failed ownership admission because its distribution-wide `service.d/10-timeout-abort.conf` appears in the broker's `DropInPaths`. The test reached shutdown only after that file was moved aside inside the disposable container. Production admission remains unchanged: distribution-wide drop-ins are not implicitly trusted. A host with such a drop-in requires an explicit retained-authority design before this restoration component can operate there; the isolated test is not evidence of support for that host configuration.

The separately ignored `setup_v3::restoration::native::native_disposable_strong_generation_restores_inactive_and_retries` fixture exercises the complete retained strong restoration body in the same explicitly marked, network-free, mount-free disposable systemd environment. It requires absent fixed product paths and fixture account names before creating two native accounts, then stages synthetic prior/candidate installation identities and exact generation retention. Both sockets are enabled and active before restoration. The test requires prior configuration, helper/sidecar, privileged launcher, product/shared history and system assets to be restored, desired and retiring user integrations to be removed, sockets to be absent and a terminal retry to be unchanged. It also requires the public strong command to remain gated. The outer runner bounds execution and removes the container after completion or failure; it does not rely on the test destructor for native cleanup.

This combined source fixture passes with both corrected native-owner publication and a retained historical root-owned workload link under [ADR 0063](0063-retained-legacy-workload-link-ownership.md). Its release claims and retained executable identities are synthetic, the old helper/launcher bytes are not executed, and no provider credential or broker process is used. It qualifies the composed fixed-path restoration with live sockets and both original link ownership forms, not authenticated release installation, active-broker termination, process-death/power-loss, set-ID workload launch or another native platform. Those remain separate gates before public strong restoration is supported.
