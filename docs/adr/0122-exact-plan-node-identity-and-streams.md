# ADR 0122: Exact plan node identity and streams

status: proposed
verification: pending

## Decision

Complete the per-node run-as and stream selection source contract for the policy-owned typed and exact-plan graphs in [ADR 0004](0004-typed-privilege-operations-and-plan-bundles.md), [ADR 0115](0115-native-administrator-grants-with-maintenance-compatibility.md) and [ADR 0119](0119-bounded-grant-output-and-native-launch-activation.md). `PlanCommand` adds optional `run_as`, `stdin`, `stdout` and `stderr` fields. Every selected field participates in the canonical plan approval digest. Omitted or JSON null fields normalize to `None` and serialize without new fields, preserving existing approved plan bytes and digests. Existing Rust constructors supply the absent fields explicitly.

`run_as` is a closed `RunAsIdentity` object containing host numeric `uid`, `gid` and a required `supplementary_groups` vector. All IDs are `u32`; the reserved `u32::MAX` sentinel is rejected in each position. At most 64 supplementary groups are permitted, with no duplicates. UID/GID zero remain valid explicit administrator-owned selections. An empty selected group vector means clear every inherited supplementary group. Missing run-as identity preserves the legacy worker root identity and inherited groups; no default account or group is inferred. Selection never performs NSS, username, group-name, credential-store or provider lookup.

The Linux x86_64/aarch64 payload child applies raw `setgroups`, `setgid` and `setuid` syscalls in that order, short-circuiting on failure before exec. Captured numeric inputs and allocated group storage are prepared and validated in the parent. The callback performs no allocation or lookup and restores the product's captured original signal mask before exec. Only payload children change identity; the trusted graph coordinator, grant guardian and cgroup owner retain their existing identities and cleanup authority. Other architectures reject selected run-as identity rather than risk different legacy syscall widths. This source contract does not qualify a new runtime platform.

The closed `PlanStreamMode` enum selects `"inherit"` or `"null"` independently for stdin, stdout and stderr. Absence preserves legacy inheritance; explicit `"inherit"` remains digest-bound and requires graph execution. JSON null is absence, while the string `"null"` selects discard/EOF behavior. When null is selected, the privileged coordinator retains a close-on-exec no-follow descriptor to the host Linux `/dev/null` character device before entering caller mounts. It verifies the protected root-owned host directory, root-owned character device 1:3 and exact opened identity. A sealed optional private snapshot marker binds the separately owned inherited descriptor and its device/inode; the worker validates that same native identity, restores close-on-exec and clones it for selected channels. The worker never opens a caller-namespace device path or procfs alias. A caller-controlled mount namespace cannot turn null selection into another device-open effect or arbitrary regular output file. No arbitrary public path, capture program or redirection syntax is added. Legacy plans carry no additional descriptor or marker.

Pipe-connected stdin/stdout must be omitted. A pipe producer with any explicit stdout selection or a pipe consumer with any explicit stdin selection fails before graph construction; wiring never overrides approved stream declarations. Unconnected channels retain their selected modes. Graph-internal binary pipes and discarded null output remain outside ADR 0119's external output accounting; the existing selected job relay still owns inherited external output limits and terminal transport.

## Authority and terminal composition

Root-owned policy and its existing typed operation/exact-plan selections remain the only plan authority. A plan selecting any per-node identity or stream mode cannot be reinterpreted as matching direct argv or native Sudo. Explicit graph selection is required, including when the selected identity or inheritance would resemble the legacy default. The existing Sudo admission boundary calls this same corrected authority check; no native Sudo grammar, credential handling or arbitrary administrator exception is widened. Separately approved unrestricted administrator authority retains its existing semantics.

The existing request's terminal selection is carried through the sealed private plan descriptor. A selected terminal uses the product-neutral terminal graph runner; a nonterminal request retains the ordinary runner. The terminal call explicitly selects `TerminalGraphSignalMask::PreservePrepared`, so shared supervision does not overwrite the product callback's original payload mask. The terminal runner owns foreground process-group routing, stopped/resumed state, binary pipe components and bounded cleanup. The original boot-time deadline callback is unchanged; resume cannot refresh the grant deadline. Held executable borrows, native argv/environment/cwd, sealed plan custody, outer cgroup admission and signal result propagation remain authoritative. No new worker or product policy is introduced into the shared command foundation.

## Compatibility and qualification

The administrator grant policy and private worker schemas remain version 1 with strictly decoded additive optional fields. Legacy plans retain their exact canonical bytes. Older readers reject selected new fields rather than dropping their effects. New selected plans require a new approval digest and a compatible product candidate; no installed approval or accepted release is reissued. The private terminal flag defaults to false and is omitted when false.

Existing grant-policy tests pin the legacy canonical bytes and SHA-256, absent/null normalization, each selected identity and stream field's digest contribution, required/bounded/unique/sentinel-free identities, strict enum/object decoding and pipe conflicts. The existing service authority regression covers both typed and exact-plan rejection of direct-argv reinterpretation. A focused metadata-only case in the existing Sudo bridge test module proves the same rejection through its actual post-policy admission function, preserving unrestricted administrator behavior. The existing sealed-worker fixture inspects the retained host null descriptor and its private identity marker, and rejects absent/invalid null-device authority before use. These are source definitions only during the compiler hold; no test-driven passing result or runtime acceptance is claimed.

Qualification must run the owning source tests and lint after the compiler hold, then native approved typed/exact-plan jobs with exact UID/GID/empty and selected groups, identity syscall failure before exec, null-device custody, every stream mode and pipe conflict, terminal foreground input, job-control stop/resume, original signal masks, expiry/cancellation and positive retained cgroup cleanup. Existing output bounds, blocked sinks, unrelated grants/non-root workloads, fresh native approval, signed setup/recovery/rollback and cross-platform gates in ADR 0115/0119 remain required.
