# ADR 0052: Restoring initial user-installation absence

status: proposed
verification: pending

## Decision

The retained Linux user-only restoration operation accepts a generation whose approved original product/shared receipts, public and transparent launchers, and active/previous pointers were all absent. Missing receipts alone are insufficient: retained unreceipted topology or incomplete receipt ownership fails closed. The full setup transition retains the exact candidate plan, candidate documents and original configuration identities and remains the authority until verified terminal restoration. Canonical native ownership, exclusive setup admission, exact retained executable execution and configuration-pair validation remain unchanged from ADR 0049.

The product derives only the approved initial candidate product/shared receipts, with no fabricated previous release. Current product ownership must equal that candidate, allowing receipt-owned transparent activation to be deactivated first, or be absent from an interrupted installation/withdrawal. A binary journal is recovered only through the shared bounded verifier admitting the exact candidate receipt. An already-partially-withdrawn installation is not passed through link repair. The product selects [retained activation withdrawal](0051-retained-activation-withdrawal.md), then removes the exact product receipt through identity-bound durable document removal. All retries retain immutable candidate bytes, installation lock, outer generation, credential material, credential-action receipts and unrelated files.

Configuration restoration preserves original bytes or removes exact approved candidate documents where the original path was absent. No original configuration, source executable or release download is required for retry. Complete absence of every approved activation path and binary journal, intact owner-controlled candidate bytes, restored configuration and inactive user integrations are required before publishing `restored_inactive`. Terminal retries verify this postcondition without rewriting it. The immutable candidate path remains the continuation executable after public aliases disappear. A new approved plan is required for subsequent activation.

This is not a complete uninstall or a retroactive fence against nonparticipating legacy writers. Unreceipted replacements are not adopted or deleted. [ADR 0064](0064-initial-strong-generation-withdrawal.md) supplies the separate initial strong composition. Initial interruption before the immutable candidate exists, signed release qualification and non-Linux custody remain separate requirements.

## Evidence

The native disposable-user CLI fixture distinguishes this capability from the former unsupported gate, restores initial v2/v3 configuration absence, removes activation and ownership receipts, preserves retention and credential-action evidence, verifies an unchanged repeat through the immutable candidate, and rejects forward recovery. A separate explicit native fixture kills the installed restoration process at its first configuration unlink, requires the retained `restoring` phase and installation receipt to survive, and resumes through that same immutable candidate before checking the unchanged repeat. Product source tests exercise partial alias/pointer/product/shared-receipt removal, both sides of initial shared-journal commit, exact journal admission, unrelated receipt/link preservation, artifact hard-link rejection, terminal continuation custody and stable installation-lock retention. These source fixtures do not establish signed release, live credential, whole-domain teardown or hardware power-loss acceptance.
