# Reusable bounded authority foundations

This focused Rust crate supplies one non-cloneable accounting core, compatible fixed leases, explicitly approved finite-duration grants, immutable operation/plan/resource binding, conserved shared/per-operation uses, replay protection and one-in-flight reusable admission. It has no product policy, native approval UI, daemon, credential input or network behavior. Products authenticate callers, obtain approval and retain native execution ownership separately. Completion permits later transactions; expiry, revocation and authority loss close admission. Gate failures do not refund authority or permit blind retries, and cleanup failures remain sticky.

The existing `LeaseLimits`/`LeaseLifecycle` maintenance facade retains its finite use budget, `remaining_uses() -> u64` and eight-hour policy cap. The separate `GrantLimits`/`GrantLifecycle` facade accepts an explicitly optional use budget and finite positive administrator-policy durations without a product-wide cap. `for_approved_duration(policy, duration)` narrows an explicit approval within that policy's idle and hard ceilings. Equal idle and hard values permit a timed overnight grant without a shorter idle cutoff. Both facades retain the historical `standard()` convenience values of thirty minutes idle and two hours hard; those values grant no permission. Trusted useful activity can reset idle expiry within the original hard deadline; polling, status and delegation cannot.

The trusted coordinator supplies observations from one native monotonic clock with the required suspension semantics. Expiry, clock regression or explicit revocation enters `Stopping`, rejecting admission without claiming that native work stopped. The coordinator cancels and joins its retained execution boundary before reporting positive cleanup. Failed cleanup remains nonterminal, and a later successful retry retains its failure history. Fixed maintenance leases also support explicit normal shutdown. Neither live facade is cloneable or serializable.

`GrantRegistry` accepts product-owned scope and authority types implementing containment. Delegation reserves finite uses from the parent; an unlimited child cannot be created from a finite parent. Delegation and observation do not refresh activity. Each admission checks the selected grant without broader fallback, and parent termination recursively stops descendants. Observation IDs are not capabilities. Terminal records may be retired only after confirmed cleanup and child retirement. This registry conserves accounting; products still own native delegated authority.

The Linux modules supply root-custodied held cgroup directories, kernel peer pidfds, fresh gated child placement, `cgroup.kill`, `populated=0` and retained child joins. The grant boundary additionally owns a separate deadline guardian process with an absolute suspend-aware timer, so stopping the coordinator cannot postpone hard expiry. Admission attaches before checking persistent revocation and guardian gates, the deadline and product-supplied native liveness. Execution preserves native argv and descriptors and applies the selected mount namespace, cwd and complete Unix identity before exec. Removal requires an empty cgroup and settled pending permits. Drop is best-effort cleanup, never successful-revocation evidence. Products still own policy/helper custody, native approval, coordinator-death enforcement, payload restrictions and service-manager crash cleanup. A cgroup alone does not contain deliberately hostile unrestricted root.

Source/synthetic tests and opt-in native fixtures are separate. Native installation, guardian enforcement, terminal transport, executable graphs, complete product containment and signed-release acceptance cannot be inferred from local lifecycle tests or cross-compilation. See ADRs 0004, 0094 and 0115 and the product qualification record.
