# Bounded administrator grants and native execution ownership

This independently versioned Rust foundation implements the lease lifecycle, scope/authority registry, conserved delegation, and Linux cgroup-v2 execution ownership in ADR 0004. It has no product policy, native approval UI, daemon, credential input, or network behavior. A product must authenticate its callers, obtain approval, supply retained native identities, and coordinate cleanup before these mechanisms constitute administrator access.

The trusted product coordinator owns the non-cloneable lifecycle, validates native caller/workload identity and policy before each admission, and supplies monotonic timestamps from one native clock with the required suspension semantics. The retained `standard()` convenience limits are 30 minutes idle and two hours hard; they do not authorize a product grant. Administrator policy selects finite positive limits without a fixed product-wide cap. `for_approved_duration(policy, duration)` narrows one explicit approval to that policy's idle and hard caps, rejecting zero and over-cap requests. Set policy idle equal to hard when a timed overnight session should remain usable without intermittent activity. Polling does not extend either deadline; accepted activity only resets idle expiry within the approved hard duration. Use exhaustion rejects a new operation without killing the last approved operation.

Expiry, clock regression, or explicit revocation enters `Stopping`, which rejects all admissions but does not claim that native work stopped. The coordinator cancels and joins its retained execution boundary before reporting complete cleanup. Failed cleanup remains nonterminal, and a later successful retry retains the failure history. There is no transition back to active and no serialization or cloning of the live use budget.

The registry accepts product-owned scope and authority types implementing containment. Delegation reserves finite uses from the parent; an unlimited child cannot be created from a finite parent. Delegation and observation do not refresh activity. Each admission checks the selected grant without broader fallback, and parent termination recursively stops descendants. Observation IDs are not capabilities. Terminal records may be retired only after confirmed cleanup and child retirement.

The Linux module requires a retained root-owned, non-delegated cgroup-v2 parent. One-use spawn permits attach the child before checking persistent eventfd revocation gates, the suspend-aware hard deadline, and product-supplied native liveness gates. Execution preserves native argv and descriptors and applies the selected mount namespace, cwd and complete Unix identity before exec. Products must supply a coordinator pidfd and verify service-manager crash cleanup. Revocation closes admission before `cgroup.kill`; removal requires an empty cgroup and settled pending permits. Drop is only best-effort cleanup, never successful-revocation evidence.

Local tests cover the lifecycle, registry, budget conservation, invalid native boundaries and a real-fork descriptor-inheritance regression. Native process enforcement, terminal transport, executable graphs and platform support require separately invoked acceptance; fake clocks and source builds do not establish those properties.
